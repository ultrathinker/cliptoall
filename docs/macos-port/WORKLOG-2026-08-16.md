## 2. ScreenCaptureKit migration

Done in two rounds by a MiniMax agent under orchestration; the review of each
round was independent, not based on the agent's own report.

**Round 1** shipped working-looking code with two defects, both catalogued:

- **#21** — capture at a quarter of the pixels. `CGDisplayPixelsWide/High`
  return **points**, not backing-store pixels, on any HiDPI display. The scale
  factor silently became 1.0 as a consequence — the exact shape of bug #7, in a
  different API.
- **#22** — pixel byte order was ABGR, not RGBA.
  `premultipliedLast | byteOrder32Little` lays bytes out as A,B,G,R; RGBA needs
  `byteOrder32Big`.

Both survived a self-test that saved a PNG and an agent that looked at it. The
saved PNG was uniformly red — the alpha channel landed in the red byte — and was
read as "matches the red wallpaper". The measured timings were meaningless
because they were taken on a quarter of the pixels.

**Round 2** fixed both and, more importantly, replaced the verification with
something that cannot be talked out of:

- the capture is compared against `/usr/sbin/screencapture -x`, an independent
  oracle shipped with macOS;
- 17 named checks that **fail loudly** rather than print numbers for a human to
  judge — dimensions, buffer length, scale, origin space, alpha opacity, channel
  permutation, three colour bands, three shear bands, drift, observer wiring;
- each of the two defects was then **deliberately re-injected** to confirm the
  checks catch them, and reverted. A test that has never failed proves nothing.

Also landed: `SCShareableContent` prewarm at startup (off the hot path), an
`NSApplicationDidChangeScreenParametersNotification` observer so a display
rearrangement invalidates the cached display eagerly, `showsCursor(false)`, and
an RGBA `CGBitmapContext` so no channel swap or stride handling is needed
anywhere downstream.

New files: `sck_capture.rs`, `sck_selftest.rs`, `sck_notifications.rs`.

**Not re-measured:** the ~270 ms `xcap` baseline is inherited from earlier
sessions, because `xcap` is no longer in the tree. The SCK numbers are fresh and
honest; the comparison is best-effort.

## 3. Stale selection rectangle — the real root cause (#23)

The previous capture's green selection rectangle intermittently appeared on the
next capture. This had been "fixed" before by drawing the new frame before
showing the window, and the fix was not wrong — it was insufficient.

**How it was diagnosed.** Instrumentation was added first, deliberately, instead
of theorising: a global hotkey timestamp so every later stage reports its offset
from the keypress, plus an unmissable log line if the 400 ms safety timer ever
fired. The result over 19 captures: **the safety timer fired zero times.** The
leading hypothesis — that the frontend was too slow and the fallback was
revealing an unpainted window — was dead.

**The actual cause.** `draw()` writes into the canvas backing store
synchronously, but the layer only reaches the screen on the next **compositor**
frame, and macOS suspends rendering for hidden windows. The overlay window is
reused, not rebuilt. So `show()` reveals the last *composited* texture — the
previous capture's final frame, rectangle and all — and only swaps to the new
content a frame or two later. Whether you saw it depended on whether the
compositor happened to wake in between, which is why it was intermittent.

Waiting for a paint before showing is impossible: a hidden window never paints,
so the wait would never return. That is bug #17, already catalogued.

**The fix.** Since we cannot control what is shown, remove anything worth
hiding. The canvas is wiped **while the window is still visible**, and the
blank frame is allowed to composite, before the result is handed back to Rust
(which is what hides the window). Applied to every exit path — selection
finished, cancelled, plugin hotkey. The cached full-screen canvases are dropped
at the same time (~48 MB per capture at 2560×1600), so no code path can redraw
the old shot. `loadAndReset` wipes again on the way in as a second line of
defence.

Cost: ~30 ms on the finish path, before the crop, imperceptible. Worst case is
now a blank flash instead of someone else's selection.

## 4. Uploaded images were soft on Retina (#24)

Not a regression — a default that was right for Windows and wrong for macOS.

`outputMode` has three values. `resize` physically downscales the capture by the
monitor scale before upload. On Windows, where scaling is typically 125–150%,
that discards little. On a 2× Retina Mac it throws away **three quarters of the
pixels**, and text in a shared screenshot comes out visibly soft.

`exif` was the answer already present in the codebase (and the one Windows
arrived at for its own version of this problem): keep every pixel, and tag the
JPEG's density so browsers still display it at logical size, per the 2021 WHATWG
density correction. Zoom and Retina viewers get full detail.

The default is now platform-dependent — `exif` on macOS, `resize` unchanged on
Windows. All three modes remain selectable on both. Existing settings files are
untouched by a default change, so this machine's setting was switched by hand.

## 5. Shared links briefly served a 1×1 image (#25)

Opening a freshly-shared Drive link sometimes showed a tiny blank image.

The cause is a documented design trade-off, not a fault: a pool of
pre-allocated ~630-byte placeholder files on Drive lets the app hand back a
real, public URL instantly, while the actual bytes are written by a background
PATCH. `Show` was already disabled during *our* upload — but our upload finishes
when the placeholder is claimed, which is only halfway. The gap was real.

The backend now emits `gdrive-content-ready` when the PATCH lands, and the
session tracks a `contentPending` flag. Only the actions that **fetch** the URL
wait on it: `Show`, and the reverse-image searches. The last of those matters
more than it looks — Google and Tineye fetch a URL once and cache the result, so
searching too early would poison the result permanently, not just show a blank.

Copying the link is deliberately **not** gated: handing someone a link they will
open seconds later is the entire point of the pool.

A 30-second client-side timeout releases the buttons if neither the ready event
nor the fallback ever arrives, so a dropped event degrades to the old behaviour
(one page refresh) rather than to a permanently dead button.

## 6. URL field is now clickable to upload

Small UX change, done by the MiniMax agent. When there is no link yet, clicking
the URL field runs the same primary action as the `Upload` button.

The neat part is the implementation: instead of attaching a click handler to a
read-only `<input>` and fighting Svelte's accessibility rules, the element
*becomes* a real `<button>` while it is actionable and reverts to an `<input>`
once a link exists. Keyboard activation works for free, screen readers announce
it correctly, no a11y rule is suppressed, and both share a class so they look
identical. When a link is present the click is not hijacked — that text is there
to be selected and copied.

Placeholder now reads `Click here or press Upload`.

## 7. Instrumentation added

The capture path already logged `+Nms` per stage, but every stage measured from
its own start, so the number that actually matters to a user — keypress to
dimmed screen — spanned two processes and was measured nowhere.

There is now a global hotkey timestamp, and three points report against it:
when JS pulls the pixel buffer, when the overlay actually becomes visible, and
an unmissable line if the safety timer fires. Enable with `loggingOn: true`.

Beware: the app rewrites `settings.json` from memory when it saves, so editing
that file while the app is running is silently undone. Stop it first.

## 9. Two lessons worth carrying

**Instrument before theorising.** The stale-rectangle hypothesis was plausible,
cheap to believe, and wrong. One log line over 19 captures killed it in seconds
and pointed at the real cause. The instrumentation cost less than the debate
would have.

**A verification you can talk yourself out of is not a verification.** Both
round-1 defects were visible in output that was looked at directly. The fix was
not more care — it was an oracle that does not argue, and assertions that fail
on their own instead of printing numbers for a human to interpret.
